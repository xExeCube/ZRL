## 2. i·j, i²·j, i³·j — the replacement for the ruled-out `k = ±1`

**Verdict: WORKS.** Verified in the 2×2 real matrix representation of Cl(1,1)
(i² = −1, j² = +1, k = ij, ij = −ji, all re-checked).

```
i⁰j = j      i¹j = k      i²j = −j     i³j = −k     i⁴j = j
```

The orbit is exactly **{j, k, −j, −k}** and closes at n = 4: a **ℤ₄ cycle** generated by
left-multiplication by i.

**Why this succeeds where `k = ±1` failed:** no element of the orbit is a scalar. `k = ±1`
collapsed the algebra by asserting that a basis element equals a number; `i^n j` gets the same
four-fold sign bookkeeping *without* that assertion, because the four objects are four distinct
algebra elements, not four values of one number.

**It costs nothing new.** This ℤ₄ is already in canon: it is the circle spec's C₄ null set
(R⁴ = 1 at θ = 0°, 90°, 180°, 270° — the quadrant map). Verified that {i⁰, i¹, i², i³} =
{1, i, −1, −i} is the same group. The idea is a *renaming of something already present*, which
is the strongest kind of confirmation available for an invented object.

## 3. Standing-wave phase {0, π} → {−1, +1}: the ℤ₂ rung

**Verdict: exact.** The author's instinct is right and the statement is clean.

A phase of 0 or π means a phase **factor** of e^{i·0} = +1 or e^{iπ} = −1. So a standing wave's
phase factor lives in **ℤ₂ = {+1, −1}**, while a travelling wave's fills all of **U(1)**.

Measured live in the app (standing preset): `max |Im(ψ/ψ_ref)| = 0.00e+0`, signs seen `{−1, +1}`.

This completes a ladder that was already half-built in canon:

```
ℤ₂ {+1, −1}          standing wave; the square's two isomers; V₄'s generators
  ⊂  ℤ₄ {j, k, −j, −k} = {1, i, −1, −i}     §2 above; the quadrant map; C₄ nulls
      ⊂  U(1)         travelling wave; the full flavor circle e^{2πik/n}
```

The flavor index n picks the rung: n = 2 gives ℤ₂, n = 4 gives ℤ₄, n → ∞ gives U(1). A standing
wave is therefore not "a wave with a degenerate phase" but **a wave whose phase has been
restricted to the n = 2 flavor**.

## 4. Conjugation IS the reciprocal map (on the unit circle)

**Verdict: exact, and it is the bridge.** The author asked whether the conjugate appearing in
the time-convention flip is "another reciprocal number". It is:

```
|z| = 1   ⟹   conj(z) = 1/z          verified, max dev 3.1e-16 over 10⁵ random points
|z| ≠ 1   ⟹   conj(z) = |z|²/z ≠ 1/z  verified, identity holds to 1.8e-15
```

Therefore, directly:

```
Re(z) = (z + 1/z)/2      = the x-bridge
Im(z) = (z − 1/z)/2i     = the y-bridge
```

**The real and imaginary parts are the two bridges.** Not analogous to them — they are them, on
|z| = 1. This is why the i-decomposition renderer and the circle renderer show the same object:
looking down the propagation axis of a plane wave in `wave_idecomp` reproduces `circle_flavor`'s
canvas exactly (verified visually: a constant-radius phasor fan through the full hue wheel).

**Practical consequence, live in the app:** the time-convention toggle e^{i(kx−ωt)} ↔ e^{i(ωt−kx)}
is exactly the swap z ↔ 1/z, and it reverses the helix's handedness. Measured: phase slope
+2.000000000 → −2.000000000, conjugation deviation 0.00e+0.

**Fourth appearance of the reciprocal-dual pattern** (canon already had {√f, 1/√f},
{R, 1/R}, {0, ∞}): now {z, z̄} = {z, 1/z} on the circle.

## 5. Co ≤ 1/√D — the proof the author could not find

This had been used as a load-bearing assumption for a long time with no proof or even a
reference located. It is a two-line von Neumann argument and it holds for **every** D.

**Scheme.** Leapfrog for ψ_tt = v²∇²ψ on a cubic lattice of spacing h:

```
u^(n+1) = 2uⁿ − u^(n−1) + Co² ∇²_h uⁿ        Co = v Δt / h
```

**Proof.** Insert a Fourier mode uⁿ e^{i k·x}. The discrete Laplacian has eigenvalue

```
∇²_h  →  −4 S ,        S = Σ_{d=1..D} sin²(k_d h / 2)  ∈  [0, D]
```

so the amplification factor g obeys

```
g² − 2(1 − 2 Co² S) g + 1 = 0
```

The product of the two roots is the constant term, **1**. Hence |g₁||g₂| = 1: either both roots
lie on the unit circle, or one lies strictly outside (growth). They lie on the circle exactly
when they are a conjugate pair, i.e. when the discriminant is ≤ 0:

```
(1 − 2 Co² S)² ≤ 1   ⟺   0 ≤ Co² S ≤ 1
```

This must hold for **every** mode, so take the worst case S = D:

```
Co² D ≤ 1   ⟹   Co ≤ 1/√D          ∎
```

**The √D is the cube diagonal.** S = D is the corner mode (k_d h = π in every axis
simultaneously) — the shortest wavelength the lattice can carry, travelling along the body
diagonal. The limit is set by the fastest-moving thing on the grid, and on a D-cube that is the
diagonal, length √D.

**Verified.** Amplification factor max|g| over 2×10⁴ random k plus the exact worst case, at
Co = 0.98/√D and 1.02/√D:

| D | 1/√D | max &#124;g&#124; below | max &#124;g&#124; above |
|---|---|---|---|
| 1 | 1.000000 | 1.000000 | 1.490835 |
| 2 | 0.707107 | 1.000000 | 1.490835 |
| 3 | 0.577350 | 1.000000 | 1.490835 |
| **4** | **0.500000** | 1.000000 | 1.490835 |
| 5 | 0.447214 | 1.000000 | 1.490835 |
| 8 | 0.353553 | 1.000000 | 1.490835 |

Independently confirmed by a real 20⁴ FDTD run: **stable at Co = 0.49, unstable at Co = 0.51**,
exactly bracketing 1/√4 = 1/2.

**Two corrections to prior belief.**
1. **There is no hard limit at D = 3.** The law holds at every D; a 4D or 5D lattice is just a
   higher-rank array and is directly testable.
2. **The D = 5 fact is a different statement.** D = 5 is where the *unit ball volume* peaks
   (ND spec §2.6, V₅ = 5.2638). It has nothing to do with the CFL condition. The two were
   being conflated.

**Where 1/√3 also shows up** (recorded, no mechanism claimed — the standing "√(2/3) triple
coincidence" note applies): 1/√3 = 0.577350 is also the cube's face signature ₂R/₀R
(ND spec §2.2). Third independent appearance of the same number.

## 6. HUYGENS — the 2D vs 3D deep dive

### 6.1 The statement

**Huygens' principle in its strong form holds only in odd spatial dimensions ≥ 3.** In 3D a
wave from a compact source passes a receiver and the field returns to *exactly* zero. In 2D —
and in 4D — a permanent decaying **wake** is left behind.

This is a theorem (Hadamard), not an approximation, and it is a third instance of the canon
theme **"dimension controls what objects exist"** (alongside: no local gravitational stress
tensor in 4D but an infinite-dimensional one in 2D CFT; no 3D division algebra by Frobenius).

### 6.2 The measurement

One physical problem — Gaussian bump of width 2.5, receiver at distance 25, periodic box of
edge 112, front arriving at ct = 25 — run at two grid spacings in each dimension.

**|ψ| / peak at fixed physical times, finest grid, identical setup:**

| ct | 2D | 3D | ratio |
|---|---|---|---|
| 40 | 7.354e-02 | 4.141e-07 | **177,586×** |
| 55 | 2.531e-02 | 1.957e-07 | **129,367×** |
| 70 | 1.348e-02 | 6.334e-07 | **21,287×** |

**4D behaves like 2D, not like 3D** (grid 70⁴):

| ct | 4D | 3D | ratio |
|---|---|---|---|
| 40 | 6.289e-02 | 4.141e-07 | 151,876× |
| 55 | 1.870e-03 | 1.957e-07 | 9,560× |
| 70 | 2.238e-04 | 6.334e-07 | 353× |

### 6.3 The discriminator that actually settles it

A large tail could always be dismissed as numerical error. The decisive test is **resolution
scaling**: hold the physical problem fixed and halve the grid spacing. A *numerical* tail
(grid dispersion) must shrink; a *physical* wake must converge to a nonzero limit.

| ct | 2D fine/coarse | 3D fine/coarse |
|---|---|---|
| 40 | 0.970 | 0.004 |
| 55 | 0.961 | 0.339 |
| 70 | 0.959 | 0.104 |
| **median** | **0.960 — converged** | **0.222 — collapsing** |

The 2D wake is **converged to within 4%** under a 2× refinement: it is physical. The 3D residual
**collapses** toward zero: it is grid dispersion. This is the rigorous form of the result and it
is what should be quoted.

### 6.4 Why — the mechanism

**Hadamard's method of descent.** A 2D solution is just a 3D solution that does not depend on z.
So a 2D point source *is* an infinite line source in 3D. After the nearest point of that line
has delivered its pulse, points farther and farther along the line are still delivering theirs,
arriving forever later and weaker. The 2D wake is the 3D line continuing to talk.

The same argument makes 4D behave like 2D and 5D like 3D: what matters is the **parity** of the
spatial dimension, because the descent by one dimension smears a sharp cone into a filled one.

### 6.5 Measured decay law

For a smooth **displacement** initial condition (ψ(x,0) = bump, ∂ψ/∂t(x,0) = 0), the 2D wake
decays as a stable power law once past the transient (2048² grid, float64):

| ct window | exponent |
|---|---|
| 250–500 | −3.552 (still transient) |
| 500–900 | −2.298 |
| 900–1300 | −2.106 |

Stable at **≈ t^(−2.1)**, consistent with the t^(−2) expected for displacement data.
**Caveat, and it matters:** the textbook "1/t wake" is the **impulse Green's function**;
smooth displacement data decays faster. Both are wakes — only the rate differs. The
qualitative fact (a wake exists at all) is what parity controls, and that is the robust claim.

### 6.6 Consequences — the actionable part

1. **A diagnostic rule for every future wave app.** Ringing behind a 3D wavefront is
   **numerical** and must shrink when the grid is refined. Ringing behind a 2D wavefront is
   **physical** and must not. The refinement test is the way to tell them apart, and it should
   be a ledger row in any FDTD build.

2. **The Echo app must not be built in 2D.** This is the load-bearing consequence. A room
   simulated as a 2D slice gives reverberation that is *qualitatively* wrong: every reflection
   smears into a 1/t²-ish tail that does not exist in a real room. Sound in air is 3D and gets
   the strong-Huygens sharp arrival — which is exactly why a hand-clap echo returns as a clap
   and not as a smear. A 2D reverb model is not a cheaper approximation of a 3D one; it is a
   different physics with a different impulse response. **Build Echo in 3D, or use an image-source
   / ray method that assumes sharp arrivals.**

3. **Why we can see and hear at all.** Sharp propagation in 3D is why a waveform arrives
   undistorted — speech would be unintelligible in a 2D world, every syllable trailing over
   the next. This is a genuinely striking fact and it earns a place in the app as a stated row.

4. **Ledger row already live** in `wave_idecomp_MIRROR.html` as a *stated* fact, with the
   measured numbers, pending the FDTD build that can compute it in-app.

## 7. The polarisation ellipse — what the helix shares with the E-vs-B picture

The author asked whether the Re-vs-Im helix is "the same thing as E-vs-B iff one is at ±180°
(or ±90°) phase of the other". **The answer is 90°, and the full structure is the polarisation
ellipse.**

Plot two co-propagating real components against each other with relative phase δ:

| δ | figure | thickness | meaning |
|---|---|---|---|
| 0° | **line** (area 0.00000) | 0.000000 | linear — **this is E-vs-B in vacuum** |
| 45° | ellipse (2.22144) | 0.414214 | elliptical |
| **90°** | **circle** (3.14159) | **1.000000** | circular — **this is the Re-vs-Im helix** |
| 135° | ellipse (2.22144) | 0.414214 | elliptical |
| 180° | **line** (area 0.00000) | 0.000000 | linear, the other diagonal |

So: **0° and 180° both give a flat line** (180° is the other diagonal, not a helix), **90° gives
the circle**. The two pictures are one family separated by the relative phase, and that family
is exactly the polarisation ellipse.

**But the objects differ, and the app says so.** E and B in a vacuum plane wave are two
*different real fields*, locked **in phase** (verified: correlation +1.000000000000) — they sit
at δ = 0 forever and can never form a helix. Re and Im are two components of *one complex
field*, locked in **quadrature** (verified: correlation 0.00e+0).

**Where the helix is genuinely physical for EM:** not as E-vs-B, but as **circular polarisation**
— the two transverse components of **E alone** (E_x, E_y) at 90°. Those really are the real and
imaginary parts of one complex Jones amplitude, and they really do trace a helix in space.

*Future feature:* exposing δ as a slider turns the app into a polarisation-ellipse explorer for
free — one control morphs the E-B-like flat figure into the helix through every ellipse between.

## 8. Paraxial beams ARE Schrödinger — the laser project reuses this solver

The paraxial Helmholtz equation for a beam envelope u(x, z),

```
2ik ∂u/∂z + ∂²u/∂x² = 0      ⟺      i ∂u/∂z = −(1/2k) ∂²u/∂x²
```

**is the Schrödinger equation with z in place of t** and 1/k in place of ℏ/m. Propagation
distance plays the role of time.

**Verified:** propagating a Gaussian with the *Schrödinger* kernel reproduces the standard
Gaussian-beam law to machine precision (worst relative error **1.6e-16**):

| z / z_R | w measured | w₀√(1+(z/z_R)²) |
|---|---|---|
| 0.0 | 4.00000 | 4.00000 |
| 0.5 | 4.47214 | 4.47214 |
| 1.0 | 5.65685 | 5.65685 |
| 2.0 | 8.94427 | 8.94427 |

with Rayleigh range z_R = πw₀²/λ = 83.7758 and far-field divergence λ/(πw₀) = 0.047746 rad.

**The two laws are the same law:**

```
beam waist    w(z) = w₀ √(1 + (z/z_R)²)          z_R = π w₀²/λ
packet width  σ(t) = σ₀ √(1 + (t/2σ₀²)²)         (ℏ = m = 1)
```

**Consequence for the planned laser project:** beam divergence, lens focusing and range
behaviour need no new solver — they are this app's packet mode with z relabelled as t.
Diffraction-limited spreading and quantum wavepacket spreading are one phenomenon in two
costumes. What *would* be new: ABCD ray matrices for lens trains (q' = (Aq+B)/(Cq+D)), the M²
beam-quality factor for real beams, and aberration (spherical aberration is the first genuinely
non-paraxial effect and the point where this equation stops being enough).

## 9. Process record — four failed runs and what caused them

Kept because the causes recur and cost real time.

1. **`buildAxes` stride bug.** Indexed `seg.length/6` where the segment stride is 12 → read past
   the array and wrote NaN into the frame buffer.
2. **Ledger reporting a domain error as a physics failure.** The packet width/norm rows FAILED at
   t = 6 purely because the packet had left the x window (Schrödinger v_g = k = 3, three times
   the EM speed); truncation narrows σ and drags the centroid inward. Now gated on a ±3σ
   containment test that reports `n/a` with the reason. **A ledger row must never report a
   domain error as a physics failure.**
3. **The periodic wrap horizon, three times.** Every Huygens run was corrupted until the
   measurement window was forced strictly inside the wrap time. Worse, the horizon is **not**
   L − r: the returning front has width, so its leading edge arrives at L − r − 3σ. The
   signature of the contamination is unmistakable in hindsight — **2D, 3D and 4D all jumped to
   nearly the same value (~3e-2) at the same time**, which is impossible for a
   dimension-dependent effect and obvious for a returning direct wave.
   *Rule: assert the horizon in code, and subtract the source width from it.*
4. **Tolerances that encode an assumption.** A "t^−1 wake" expectation and a 1e-6 circle
   tolerance both failed against correct data. The first was the wrong Green's function (impulse
   vs displacement); the second was a duplicated endpoint in `linspace`. *Measure, then fit;
   do not assert an exponent and test for it.*

Also worth keeping: the `pytest`/numpy failure that looked like a per-folder plugin problem was
neither — `pytest.exe` on PATH launches **Python 3.9** (no numpy) while `python` is **3.12**
(numpy 2.5.1, no pytest). `python -m pytest` forces the named interpreter to be the one that
runs. All **37** oracle tests pass under it (2026-09-17).
